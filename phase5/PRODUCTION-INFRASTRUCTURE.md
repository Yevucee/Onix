# Production infrastructure requirements

Onix website replacement — self-hosted Next.js + Payload CMS + PostgreSQL.

## Architecture overview

```
[Internet] → [Reverse proxy + TLS] → [Next.js/Payload app :3000]
                                          ↓
                                    [PostgreSQL 16]
                                          ↓
                                    [Media volume]
```

Outbound: SMTP/email API, newsletter provider API, optional GA4.

---

## Minimum viable production

| Component | Specification |
|-----------|---------------|
| CPU | 2 vCPU |
| RAM | 4 GB (2 GB app + 2 GB PostgreSQL) |
| Disk | 40 GB SSD (OS + DB + 2 GB media headroom) |
| OS | Ubuntu 22.04 LTS or Debian 12 |
| Node.js | 20 LTS |
| PostgreSQL | 16 |
| Docker | 24+ (recommended) or native Node + systemd |
| TLS | Let's Encrypt via reverse proxy |
| Backup | Daily DB dump + weekly media archive |

Suitable for low-traffic corporate site with ~88 articles and moderate form volume.

## Environment variables

See `.env.example` for full list. Production requires:

- `SITE_ENV=production`
- `DATABASE_URL`
- `PAYLOAD_SECRET`
- `NEXT_PUBLIC_SITE_URL=https://onixdatacentres.com`
- `CONTACT_FORM_RECIPIENT`
- `EMAIL_PROVIDER` + credentials
- `NEWSLETTER_PROVIDER` + credentials (if used)
- `GA4_MEASUREMENT_ID` (at launch)

Do **not** set `STAGING_AUTH_*` or `STAGING_SEND_EMAIL` in production.

---

## HTTPS / reverse proxy

- Terminate TLS at reverse proxy
- Proxy to `localhost:3000` (app container)
- Set `X-Forwarded-Proto`, `X-Forwarded-Host`
- Force HTTPS redirect
- Secure cookies require HTTPS in production

Example nginx location block documented in `docs/deployment.md`.

## DNS requirements

| Record | Purpose |
|--------|---------|
| A/AAAA `onixdatacentres.com` | Production app server |
| A/AAAA `www.onixdatacentres.com` | Redirect to apex or serve www |
| MX | Unchanged until email migration decided |

Staging uses separate hostname (e.g. `staging.onixdatacentres.com`).

## Media & disk

- Migrated library: ~1.5 GB
- Growth allowance: 2× headroom minimum
- Responsive variants generated by Sharp on upload
- Backup: rsync or tar to object storage

---

## Security

- Secrets in environment only (not Git)
- Payload admin behind same origin + strong passwords
- Rate limit `/api/contact` and `/api/newsletter`
- Upload validation (MIME, size limits)
- Regular OS and dependency updates

---

## Scaling notes

Current architecture is single-node. For future scaling:

- Read replicas for PostgreSQL (Payload read-heavy pages)
- Object storage for media (S3-compatible)
- Horizontal app replicas behind load balancer (stateless Next.js)

Not required for initial launch.
